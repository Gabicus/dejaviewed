OpenScreen — Free Open-Source Screen Studio Alternative

GitHub: https://github.com/siddharthvaddem/openscreen License: MIT Stack: Electron + React + TypeScript + Vite + PixiJS + Tailwind Platforms: macOS 13+, Windows, Linux (PipeWire) Repo path: repos/openscreen/ (clone pending — sandbox blocked git clone in this session; run git clone https://github.com/siddharthvaddem/openscreen.git repos/openscreen manually)

What it is

OpenScreen is a free, open-source desktop screen recorder built as a deliberate clone of Screen Studio — the $229 macOS app that single-handedly defined the "polished product demo with smooth auto-zoom and animated cursor" aesthetic that's now everywhere on X and YouTube. The creator's pitch is refreshingly honest: "a much simpler take, just the basics for folks who want control and don't want to pay."

That framing is accurate. OpenScreen is not trying to match Screen Studio feature-for-feature. It nails the core that makes Screen Studio recordings instantly recognizable — automatic cursor-aware zooms, cinematic backgrounds, motion blur, clean exports — while skipping fancier pro features. In exchange you get: free, MIT-licensed, cross-platform (Mac / Windows / Linux), and source available.

The closest analogs:

Screen Studio — $229, macOS only, polished, the gold standard; OpenScreen clones its core loop

Cap — open-source, Rust + Tauri, more feature-rich, focused on async video messaging (Loom-style)

Tella — cloud-hosted SaaS, polished but subscription and not local

OBS Studio — free, pro-grade, zero polish (no auto-zoom, no cursor animation)

QuickTime / Windows Snipping Tool — free but bare-metal, no editing

OpenScreen sits in the "free and polished enough for 90% of demos" slot that nothing else really filled before — Cap is close but much heavier.

How it works

OpenScreen is an Electron desktop app. The recording and editing pipeline is:

Capture — Electron's desktopCapturer API pulls a MediaStream for the selected screen/window. On macOS 14.2+ it requests the audio capture entitlement; on Linux it relies on PipeWire's screen capture portal. Windows has first-class system audio support.

Cursor tracking — alongside the video stream, OpenScreen records high-resolution cursor position events. This is the secret sauce: because cursor data is captured as discrete events rather than baked into the video, the editor can later generate smooth animated cursors and compute zoom targets that actually track where attention is.

Editor / compositor — a PixiJS scene composites the raw screen recording, a generated synthetic cursor (styled and animated), a background layer (wallpapers, colors, gradients), and effects like motion blur. PixiJS gives it hardware-accelerated 2D rendering which is why the preview is smooth.

Timeline — built on dnd-timeline for draggable segments, trims, and speed ramps.

Auto-zoom engine — analyzes cursor velocity and click events to place zoom keyframes automatically; you can also drop manual zooms with configurable depth and duration.

Export — renders the composed timeline out to MP4/WebM at configurable aspect ratios and resolutions.

Core features (what actually works)

Record a specific window or the full screen

Automatic zooms driven by cursor/click events, with adjustable depth and duration

Manual zoom keyframes on the timeline

Animated synthetic cursor — larger, smoothed, styled separately from the OS cursor

Microphone + system audio capture (system audio on Windows and macOS 14.2+; Linux via PipeWire)

Background customization — wallpapers, solid colors, gradients

Motion blur effect for smooth zoom transitions

Annotations — text, arrows, images

Segment trim, split, speed adjust

Multiple aspect ratios (16:9, 9:16, 1:1, etc.) and export resolutions

Local-first, no cloud, no account

System requirements

macOS: 13 Ventura or later; macOS 14.2+ recommended for system audio capture

Windows: 10/11, works with system audio out of the box

Linux: Must have PipeWire (most modern distros — Fedora, recent Ubuntu, Arch — do); X11-only systems won't work

RAM: 8 GB minimum, 16 GB recommended for 4K/long recordings (Electron + PixiJS + raw frame buffers add up)

GPU: Any modern integrated GPU; PixiJS uses WebGL

Disk: Enough free space for raw recordings — plan ~1 GB per 5 minutes at 1440p

Quick start

Install from releases (recommended): Download from the GitHub Releases page.

macOS:

After downloading the .dmg and dragging to Applications

xattr -rd com.apple.quarantine /Applications/Openscreen.app open /Applications/Openscreen.app

(The xattr step is required because the app isn't notarized — Gatekeeper will otherwise refuse to launch it.)

Linux (AppImage):

chmod +x Openscreen-Linux-.AppImage ./Openscreen-Linux-.AppImage

Windows: run the installer .exe.

Build from source (for hacking or if no release matches your platform):

git clone https://github.com/siddharthvaddem/openscreen.git cd openscreen npm install npm run dev # launches Electron in dev mode with hot reload npm run build # produces a platform installer in dist/

Gotchas

No notarization on macOS — every release needs the xattr dequarantine step or Gatekeeper blocks it. If you share a recording workflow with non-technical people, point them at a notarized alternative instead.

Linux system audio is hit-or-miss. PipeWire portal support varies by distro and desktop environment. If system audio doesn't work, fall back to capturing mic + running the app's audio through a virtual sink.

Electron overhead. Startup is 1-2 seconds slower than native apps, and RAM usage sits around 400-700 MB while idle. Not ideal for older laptops.

Feature gap vs Screen Studio: no multi-camera picture-in-picture, no advanced speed ramps, no per-clip color grading, no teleprompter. If those matter, stay on Screen Studio.

Project is young. Expect rough edges, occasional crashes, active development. Check the issue tracker before committing to it for mission-critical recordings.

Bottom line

OpenScreen is a legitimately useful free alternative to Screen Studio for the exact style of product demo everyone is making in 2026. The feature set is narrower than Cap but more focused on the cinematic-demo aesthetic, and it works on Windows and Linux where Screen Studio does not. Worth cloning, worth having installed, worth using for any public-facing recording that doesn't justify a Screen Studio license.

Step 2 — Install and capture check on Fedora Wayland

Goal: Get screen, mic, and system audio capturing through the PipeWire portal.

Install the latest AppImage from Releases (chmod +x, run from a terminal so logs print). If none exists or it fails, build from source in repos/openscreen with npm install and npm run dev, then npm run build. Record which path worked and the exact versions (Electron, Node, release tag).

Step 3 — Calibration take: sync, frames, size, RAM

Goal: Measure the tool's technical limits on this machine.

Generate a sync clip: ffmpeg -f lavfi -i 'color=black:s=1920x1080:r=60' with a white flash frame every 2 s and a 1 kHz beep aligned to each flash, 10 minutes long (build it with lavfi color, drawbox or overlay, and sine with volume gating; verify alignment in the generated file first). Repeat the 10-minute take in OBS for a baseline. Write calibration.md with a table OpenScreen versus OBS.

Audit before moving on: Verify the reference clip itself has 0 ms offset before blaming the recorder. 5 · What proves it right

ffprobe on both exports: spec resolution, codec, and constant frame rate within 1%.

Flash-and-beep calibration measured with ffmpeg signalstats and silencedetect: offset under 45 ms at start and under 80 ms at 10 minutes.

ffmpeg ebur128: integrated loudness -14 plus or minus 1 LUFS and true peak at or below -1 dBTP.

A viewer who did not record it watches the 9:16 export on a phone and correctly names the three clicked actions.

Private upload to YouTube or X processes cleanly at full resolution.

A 1 fps frame scan of the final exports finds no secrets or private data.

6 · Failure modes

Portal captures video but no system audio. Tell: ffprobe shows a single mic stream; tone missing on playback. Fix: per-session null sink and record its monitor, or record audio separately and mux with ffmpeg.

Variable frame rate export drifts after upload. Tell: sync fine locally, off on YouTube. Fix: re-encode to constant frame rate with ffmpeg -fps_mode cfr at the spec rate.

Auto-zoom lands on empty screen because the cursor moved while thinking. Tell: zooms between clicks. Fix: rehearse cursor paths, park the mouse, replace bad keyframes with manual zooms.

Secrets on screen. Tell: frame scan shows an API key in a terminal or an email in a browser tab. Fix: delete the take, clean the session, re-record; never blur and publish.

App crashes or drops frames on long takes. Tell: duplicate-frame count climbs with time, RSS grows. Fix: cap take length per spec, split into segments, or use OBS for long recordings.

Loudness inconsistent across videos. Tell: ebur128 readings vary by more than 3 LU. Fix: always run two-pass loudnorm at -14 LUFS as the last step.

9:16 crop cuts off the action. Tell: frame grabs show the click target outside the frame. Fix: re-key zooms specifically for the vertical export.
