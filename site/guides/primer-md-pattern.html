primer.md — The Living Handoff Document Pattern

In short: Implement the primer.md living-handoff pattern (credited to @keshavsuki, lineage from @ykdojo's HANDOFF.md) in a real project so every Claude Code session starts from an accurate state snapshot and ends by rewriting it, without the human remembering.

Attributed to: @keshavsuki (on X/Twitter), though the broader "living handoff document" lineage predates the specific primer.md naming — Yusuke Kamiyamane (@ykdojo) popularized a similar HANDOFF.md pattern, and various SESSION.md / STATE.md / CONTEXT.md variants circulate in the awesome-claude-code ecosystem. The primer.md naming and the specific "Claude rewrites it at session end" mechanic are the contribution being catalogued here.

Research note: The specific @keshavsuki post was not directly recoverable through web search at the time of writing. The pattern described below is reconstructed from the broader family of handoff-document patterns it belongs to, cross-referenced with the Claude Code hook system that makes the "auto-rewrite on session end" mechanic possible. Treat specific code snippets below as reference implementations, not verbatim copies of keshavsuki's original.

What it is

primer.md is a sibling file to CLAUDE.md that serves a fundamentally different purpose:

CLAUDE.md = permanent project knowledge (conventions, stack, behavioral rules). Rarely changes.

primer.md = live project state (what's happening right now, what's blocked, what's next). Rewritten every session.

The core mechanic: at the end of every Claude Code session, Claude rewrites primer.md with a snapshot of where the project currently stands and what the next session should do first. At the start of every session, Claude reads primer.md (via a CLAUDE.md pointer or via the additionalDirectories hook) and resumes exactly where the previous session left off — no "what were we doing again" dance, no re-reading five files to rebuild context.

It is a living handoff document between Claude and its future self.

Why this pattern exists

Claude Code has no memory across sessions. Every new session starts cold. The options for rebuilding context are:

Re-explain to Claude manually — slow, lossy, requires you to remember.

Rely on CLAUDE.md — it holds permanent rules but not current state ("we just finished phase 2, phase 3 is blocked on the Redis migration").

Use /resume — works within a single conversation thread but not across branch-switches, compactions, or new terminals.

Ask Claude to write a handoff document before starting fresh — the @ykdojo pattern. Works, but requires you to remember to ask.

Make the handoff document self-maintaining — the primer.md pattern. The hook handles it automatically.

primer.md is option 5, and its value is that it removes the human from the loop. You never have to remember to update it.

How it works under the hood

The pattern has three parts:

1. The file itself — structured session state

Project Primer

_Last updated: 2026-04-08 14:32 UTC (session ended)_

Current status

Phase 3 of the trading-agent-team integration. Arena wire-up is COMPLETE and green. Legion port is IN PROGRESS — we're 60% through migrating the Command tab from /finance into /unicron/command.

What changed this session

Ported ARSENAL tab component + its three sub-widgets (bot cards, metric

rows, status dots). Tests green.

Discovered: the old Legion Command chart code depends on Plotly 5.x;

/unicron is on Plotly 6.x. Needs shim or upgrade.

Added your CSS vars to src/styles/legion-theme.css.

Next up (start here)

Resolve the Plotly version mismatch — decide: shim or upgrade all of unicron.

Relevant files: src/charts/LegionChart.tsx, package.json (line 42).

Finish migrating RANKINGS tab (parallel structure to ARSENAL — should

be ~30 min if Plotly is resolved).

Run full visual-regression suite before declaring Phase 3 done.

Blockers

Plotly version decision (above). Needs your input if we go the

upgrade route since it touches other tabs.

Open questions

Does the old session_state singleton in legion_command.py need to

survive the port, or can we replace it with Zustand like the rest of unicron?

Don't forget

The .env in /unicron has a placeholder HL_PRIVATE_KEY — you

need to set this before running live.

Arena's WebSocket reconnect logic is the reference implementation for

any new real-time wiring.

Key sections:

Current status — one paragraph, no more. Where is the project right now?

What changed this session — delta from last primer. Keeps momentum visible.

Next up — explicit ordered list. First item should be immediately actionable by a fresh Claude with zero other context.

Blockers — things that need human input or external resolution.

Open questions — uncertainties worth surfacing before the next session dives in.

Don't forget — sharp edges, gotchas, state that lives outside the code (env vars, external services, half-applied migrations).

2. The CLAUDE.md anchor — tell Claude the file exists

Add this to your project CLAUDE.md:

Session continuity

At the start of every session: read primer.md first. It contains

the current project state and next steps from the previous session.

Follow the "Next up" list unless the user redirects.

At the end of every session: rewrite primer.md from scratch.

Do not append — the file is a snapshot, not a log.

Structure: Current status / What changed / Next up / Blockers / Open

questions / Don't forget.

Keep it under 150 lines. If it's growing, something is wrong — the

project has either stalled or needs a real retro.

3. The hook — automate the rewrite

Claude Code hooks (configured in .claude/settings.json) can run arbitrary commands on lifecycle events. The relevant one here is the Stop hook — fires when a session ends (user exits, or agent finishes its final turn).

{ "hooks": { "Stop": [ { "matcher": "", "hooks": [ { "type": "command", "command": "claude -p 'Rewrite primer.md to reflect the current project state. Use the structure defined in CLAUDE.md under Session continuity. Do not append — replace the file entirely. Be specific about what the next session should do first.' --allowedTools Read,Write,Glob,Grep" } ] } ] } }

How this works:

Session ends → Stop hook fires.

The hook spawns a fresh claude -p (non-interactive) subprocess.

That subprocess reads the current transcript context (via the CLAUDE_TRANSCRIPT_PATH env var the hook provides), analyzes what happened, and writes a new primer.md.

The subprocess is restricted to Read,Write,Glob,Grep — it can't accidentally run tests, commit, or touch anything else.

Next session starts → reads primer.md per the CLAUDE.md instruction → resumes cleanly.

Alternative: PreCompact hook. If your sessions are long and you rely on compaction rather than explicit exits, use the PreCompact hook instead. Same logic, fires before Claude Code compresses context rather than when the session terminates.

Alternative: manual command. If you don't want automation, add a slash command:

.claude/commands/prime.md

Rewrite primer.md with the current project state per the structure in CLAUDE.md. Then summarize what you wrote in 2 sentences.

Now /prime at the end of any session does the same thing without a hook.

Key mechanics

What makes primer.md different from HANDOFF.md / SESSION.md / a changelog:

Snapshot, not log. It is rewritten, not appended to. This is critical — a log grows unboundedly and loses the "what matters now" signal. A snapshot stays focused.

Self-maintaining via hook. The human never types it. This is what keshavsuki's contribution adds over the manual handoff pattern.

Action-oriented "Next up." The first line of the first next-up item should be immediately executable. No "continue working on the thing" — specific file, specific change.

Paired with CLAUDE.md, not replacing it. CLAUDE.md is permanent rules; primer.md is state. Don't conflate them.

Gotchas

Rewrite, don't append. The moment you start appending, primer.md becomes a changelog and loses its "next session starts here" focus. Enforce this in the CLAUDE.md anchor.

The Stop hook runs a second Claude call. That's extra tokens and a few seconds of latency on exit. Worth it for important projects; overkill for throwaway scripts.

Hook failures are silent by default. Test the hook with claude --debug the first time you set it up. JSON syntax errors in .claude/settings.json kill hooks without warning.

Don't put secrets in primer.md. It's meant to be committable. If you need to note "set HL_PRIVATE_KEY before running," reference the variable name, never the value.

Git commit it. primer.md should be in version control so team members (or your future self on a different machine) can pick up state too.

Size discipline. Target ~100 lines. If it balloons past 200, the project has either stalled (too many open questions accumulating) or needs a real retrospective — not a longer primer.

Don't read primer.md in CLAUDE.md twice. If you load primer.md via additionalDirectories AND reference it in CLAUDE.md, Claude sees it twice. Pick one mechanism.

What we could build with it

A primer-md skill that formalizes the rewrite discipline with a structured prompt — handles the rewrite-not-append rule, enforces the section structure, checks length budget.

A /prime slash command with a PreCompact + Stop hook preset — one-command setup for any project.

A primer.md → MEMORY.md bridge — if the session ended with a significant milestone, also update your global memory index.

A fleet primer dashboard — scan all projects under ~/projects/, read each primer.md, render a single "status across all projects" view. Natural fit with your /flywheel and /status skills.

A primer-diff alarm — alert if primer.md hasn't changed in N days (project stalled) or if the same "Next up" item has persisted for N sessions (blocked, needs human intervention).

A Git-aware primer — cross-check primer.md's "What changed" section against actual git log since last rewrite, flag discrepancies (primer lies, or work that never got committed).

Step 1 — Ground truth: hook semantics for this version

Goal: Replace the guide's hook assumptions with documented and observed behavior.

For each event (SessionStart, Stop, SubagentStop, PreCompact, SessionEnd) record: when it fires, matcher support, stdin JSON fields (look for session_id, transcript_path, cwd, hook_event_name, reason, trigger), exit-code meanings, timeout default, and output options (additionalContext for SessionStart).

Step 2 — Template and linter

Goal: Define what a valid primer is and enforce it mechanically.

Write templates/primer.md with the six sections in order: Current status (one paragraph), What changed (bullets), Next up (numbered, item 1 immediately executable with a file path or command), Blockers, Open questions, Don't forget; plus a Last updated line with UTC timestamp and session id.

After the child exits, run lint_primer.py; on failure restore primer.prev.md and write the lint errors to primer.lint.log.

Wire it in .claude/settings.json of the scratch project for SessionEnd and PreCompact only. Validate the JSON with jq before saving. Run three sessions with --debug, including one with /compact and one killed with kill -TERM.

Write gap_report.md: every guide claim (Stop hook at session end, CLAUDE_TRANSCRIPT_PATH, additionalDirectories reading, hooks skipping on JSON errors, /prime fallback) and every deliverable, marked verified / unverified / false with evidence, ranked by impact. 5 · What proves it right

claude --debug logs across exit, /compact, and multi-turn sessions: exactly one rewrite per exit and per compaction, zero per turn, zero recursive.

lint_primer.py passes on 10 consecutive automatic rewrites, and its 8-fixture test suite returns 8/8 expected results.

git log -p primer.md: each version's What changed matches that session's code commits, and the linter finds no secret pattern in any version.

Blind resume trial, 5 sessions per arm on an identical commit, scored by a reviewer who did not write the primer: primer arm lower median time to first correct action and fewer clarifying questions.

6 · Failure modes

Rewrite on every turn. Tell: debug log shows the hook after each response; token use balloons. Fix: move to SessionEnd and PreCompact.

Recursive rewrites. Tell: many claude processes spawn at exit. Fix: PRIMER_REWRITE=1 guard checked first in the script and set for the child.

Rewriter has no context. Tell: primer.md becomes generic or repeats the previous version. Fix: pass transcript_path from stdin and the git log into the prompt.

Blockers silently dropped. Tell: an open blocker disappears without a matching fix in git. Fix: prompt requires carrying forward unresolved items; diff check against primer.prev.md.

Primer commit sweeps other files. Tell: git show --stat lists code files. Fix: commit only when nothing else is staged and add primer.md by explicit path.

Session killed, no rewrite. Tell: Last updated stamp older than recent commits. Fix: /prime manual command and a SessionStart warning when the stamp is stale.

Primer grows into a log. Tell: line count creeps toward 150. Fix: linter cap and a retro when it is hit.
