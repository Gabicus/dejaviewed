50k ft — Why care?

A speed recipe for strategy grid searches with VectorBT: load OHLCV via numpy memmap (mmap_mode='r', copy=False) to avoid RAM blowups, fan thousands of backtests across cores with joblib Parallel, batch tasks in groups of 1,000, and run Portfolio.from_signals with fees and slippage as Numba-compiled matrix ops. Illustrated with a BTC moving-average crossover return surface.

10k ft — Key takeaways

• Always pass fees and slippage into Portfolio.from_signals so grid winners are not fee artifacts. • Batch joblib tasks to keep all cores saturated and cut process overhead. • More accessible entry point for retail → quant transition • Use np.load(..., mmap_mode='r') and DataFrame(copy=False) to backtest many tickers without RAM spikes. • VectorBT enables fast vectorized strategy backtesting
