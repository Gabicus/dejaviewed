50k ft — Why care?

Five backend/frontend performance gaps in AI-written apps: uncompressed JSON responses, row-by-row database inserts, a single dependency bottleneck in round-trip latency, no optimistic UI updates, and server re-rendering HTML for every visitor instead of caching.
UI/UXsoftware developmentvideo production

10k ft — Key takeaways

• Batch database writes • Enable gzip/brotli on API responses • Profile round-trip latency to find the one step taking ~90% of time • Update UI optimistically and cache rendered pages

5k ft — Tools & techniques

Claude, Claude Code batch writes, latency profiling, optimistic UI, response compression, static caching

Transcript excerpt
If Claude writes all of your code, your app is painfully slow and you don't even realize it yet. So here are the five things it probably forgot to do. Don't worry, all of these are vibe-codable changes you just need to know to ask for them. Number one, your JSON is going over the wire uncompressed, which just makes everybody wait longer for everything your backend server responds with. Number two, your app is writing new rows to your database one at a time, which increases overhead for no reason. This isn't something that you would notice at one user, but at a thousand users your app would feel like molasses. Number three, you have a single dependency bottleneck. To identify this, you can audit your roundtrip latency and break it down into specific network events. If one action is taking 90% of the roundtrip time, that is your bottleneck. Number four, every single action the user takes waits on the response from the backend before updating anything in the user interface. Number five, your frontend web server is rebuilding HTML for every visitor that loads up the site.
