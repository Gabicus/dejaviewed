Transcript excerpt
It turns out that teaching your Claude to speak like a caveman is one of the most effective ways to reduce its token usage. However, it's a bit inconvenient, so if you're burning through tokens, here are three alternative methods that you can use to reduce your usage. The first thing you need to make sure you're doing is using skills and using the skill creator plugin seen above to make your own skills. The reason they exist is so that Claude has a way to find specific contexts and actions about what it needs to do without burning tokens looking through all your project files for what it needs to perform. Next is being aware of your context usage, which means that if you're using 1 million context windows, you are naturally going to burn more than if you were using 200K and if that you are using more than 60 to 70% of your context in a session without clearing is that the effectiveness goes significantly down once it reaches that point. Last, is having clean file structure for your projects. Effectively, it should read out like a map when your Claude goes in there to find what it needs to perform what you ask for. If you want a good example of this, check out this gentleman right here. He has a really good breakdown on good file structure when using Claude code specifically. I can say that while developing two different softwares and managing operations for multiple companies, is that I have rarely hit my limit for my plan, which I can accredit to using these three methods…
